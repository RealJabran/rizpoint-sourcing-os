# Private user guide

Sign in at `/login` using the owner account provisioned by the deployment operator. Start a scan from Uploads, choose the worksheet and header, save or select a mapping profile, then wait for normalization, matching, enrichment, and calculation states. Treat `PARTIAL_SUCCESS`, stale evidence, PackGuard blocks, and review states as required actions rather than successful purchasing decisions. Only shortlist results with complete evidence and use a validated purchase order before exporting. Export links are private and expire.

If an inspection retry budget is exhausted, use **Retry inspection** on the upload page after the dependency recovers; it reuses the existing private object and checkpoint. For later scan stages, retain the scan ID and retry through the workflow; do not re-upload solely to bypass a transient provider or worker failure. Report any unexplained financial value, duplicate work, cross-organization data, or accepted pack contradiction as a Sev-1 issue.

For one product, open **Product Research → Research product** and enter an ASIN,
UPC/EAN/GTIN, or Amazon product URL. An optional sale price makes the fee
scenario explicit; otherwise RizPoint uses a valid current featured offer when
available. Results distinguish live Amazon, stored Amazon, and demo data and
show marketplace, observation time, freshness, and completeness. Save or watch
products by choosing a named project—never by copying an internal ID.

Use **Amazon catalog search** on the same page for a bounded seed-keyword result
set. Treat it only as returned Catalog Items, not market size, search volume, or
demand. Select up to five results for full product research.

Open **Settings → Integrations → Market history** for the optional licensed
history state. If it says **Provider required**, no historical series will be
invented from SP-API. See `docs/LIVE_RESEARCH_VERTICAL_SLICE.md`.
